# Usage

The program offers multiple command line arguments. `--steps`, `--algorithm`, and one of `--num-neurons`, `--num-neurons-per-rank`, and `--file` are required, the rest is optional.

If the program is compiled with CUDA enabled, `--algorithm` only accepts `naive-cuda` or `barnes-hut-cuda` at runtime; every other algorithm choice is rejected.

## GPU / CUDA sizing

These options only take effect when the program is compiled with CUDA enabled.

### Memory layout for GPU edge storage

Each neuron's edge/synapse storage on the GPU (local and distant, incoming and outgoing) is a
dynamically growable array with a two-tier layout, designed to avoid provisioning every neuron
for a worst case that few neurons actually hit:

1. **Non-overflow (main) chunk** -- a fixed-size buffer allocated up front, individually, for
   *every* neuron. Its size is `--non-overflow-size-factor` times `--expected-synapses-per-neuron`,
   further split between local and distant edges by `--local-edges-ratio` (the fraction going to
   local edges; distant edges get the remainder). This chunk is never shared with other neurons,
   so its cost scales with the neuron count regardless of whether any given neuron ever needs it.
2. **Overflow chunks** -- once a neuron's main chunk fills up (its actual edge count exceeds what
   was provisioned), it starts drawing additional, smaller chunks from a *shared* pool
   (`SharedBlockPool`) instead of getting a bigger private buffer. Each chunk's size is
   `--overflow-chunk-size-factor` times `--expected-synapses-per-neuron`, and the total number of
   chunks pre-allocated in the pool is `--number-overflow-chunks-factor` times the number of
   buffers sharing it (neurons times the number of edge-storage instances involved). The pool
   cannot grow during a kernel launch -- if every neuron that needs to overflow can't get a chunk,
   the append silently fails (dropped edges), so `--number-overflow-chunks-factor` is a safety
   margin, not a hard cap that's safe to shave down without headroom to spare.

`--expected-synapses-per-neuron` is only an *average* estimate; real per-neuron edge counts vary.
The two-tier split exists so that the common case (a neuron close to the average) is served
cheaply out of its own main chunk, while the statistical tail (neurons that end up with far more
edges than expected) borrows from a pool sized for the *aggregate* overshoot across all neurons --
which is far cheaper than inflating every neuron's private main chunk to cover the worst case.
Concretely: if you see dropped edges or pool-exhaustion errors, raise
`--number-overflow-chunks-factor` (more chunks) or `--overflow-chunk-size-factor` (bigger chunks)
before reaching for `--expected-synapses-per-neuron` or `--non-overflow-size-factor`, which scale
the up-front, per-neuron cost instead.

 Command                                        | Shortcut            | Effect                                                                                                                                                                      | Notes
------------------------------------------------|---------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------
 `--expected-synapses-per-neuron <uint64>`      |                     | Expected number of synapses per neuron, used to size GPU edge storage                                                                                                       | Default is `100`                                                                                                                  |
 `--non-overflow-size-factor <double>`         |                     | Fraction of expected synapses per neuron used as the non-overflow (main) chunk size, allocated up front for every neuron                                                    | Default is `0.8`                                                                                                                  |
 `--overflow-chunk-size-factor <double>`       |                     | Size of a single overflow chunk (as a fraction of expected synapses per neuron), drawn from a shared pool once a neuron's main chunk fills up                              | Default is `0.2`                                                                                                                  |
 `--number-overflow-chunks-factor <double>`    |                     | Multiplier for how many overflow chunks are pre-allocated in the shared pool                                                                                                | Default is `2.0`                                                                                                                  |
 `--local-edges-ratio <double>`                |                     | Fraction of the non-overflow chunk budget given to local edges; distant edges get the remainder                                                                            | Default is `0.7`, must be from `[0, 1]`                                                                                           |

### In case you have compiled the program with MPI, you can also prefix the command with: `mpiexec -n 4 ...`

However, if you do so, the number of MPI processes must be a power of 2 (i.e. $2^n$).
